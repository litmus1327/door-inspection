2. Assisted mode ("training wheels"). A toggle that switches the whole app between novice and expert presentation. Critical design rule: it changes presentation ONLY, never the inspection logic or guardrails. Both modes run the same `getApplicableItems`, blocking prompts, rating checks, required-field validation, and review. What differs:
   - Assisted on: hardware photo cards, assembly/rating descriptions, label example photos, Diagram view by default, (later) per-item reference photos.
   - Assisted off (expert): compact hardware toggles, dropdowns without the picture clutter, Checklist view by default. Same guardrails, faster.
   Refinements Derek wants: persist the preference per inspector (v1 can be a saved localStorage flag; later attach to inspector profile), and label it "Assisted mode" in the UI (keep "training wheels" internal only).

## Gotchas

- The truncated-file-read and sandbox-VM issues from the Cowork session were artifacts of that sandbox and will NOT occur in Claude Code (it runs locally). You can trust `pnpm check` and the running app directly.
- `pnpm start` in the repo uses POSIX env syntax; on Windows PowerShell run `$env:NODE_ENV='production'; node dist/index.js`. `pnpm dev` and `pnpm check` work as-is.
- Reporting Tool export details: assembly codes map to strings like `1-Hour Fire` (no "Barrier"); ratings as `90 Minute`; deficiencies as `Yes: <Category>: <Detail> (INITIALS) - YYYY-MM-DD`. Inspector shows as initials unless the initials are in the Reporting Tool's `config/inspectors.json`.
